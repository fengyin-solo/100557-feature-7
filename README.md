# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。

### 洁净区归属与流转规则

规则集中在 `src/data/cleanroom-domain.ts`（区划/轮值/批号）与 `src/api/local-service.ts`
（`checkCleanroomAction` 闸门），页面只渲染、不做业务判断。

- **点位划片归属**：每个监测点位固定属于一个生产区（A/B/C）。只有归属区的监测人能对该点位
  「提交监测 / 判定达标 / 标记超标」，其他区一律拒绝，返回信息写明归属区与越权原因。
- **监测人按周轮换**：各区监测人名单固定，按 ISO-8601 周序号在名单中轮换；只有本周当班监测人
  有权操作。页头下拉可切换身份（用于演示），本周当班人带「（本周当班）」标记。
- **达标即只读**：判定达标的记录转为只读，任何区（含归属区）都不能再提交或标记。
- **状态只顺次推进**：待监测 → 监测中 →（已达标 / 超标预警）；倒序、往回走一律挡回。
  超标与达标是监测中的两个前向判定终态。
- **重复标记只算一次**：同一动作命中同一状态时拒绝，提示「只算一次，无需重复操作」。
- **培养基批号跟点位对应**：批号按点位固定分配（`MED-<区码>-<序号>`），提交时填写不一致直接打回。
- **悬浮粒子数双录一致**：两处独立录入，均须为非负整数（文字、负数、小数、空值打回重填），
  两处不一致按「取来的不是同一份」打回；落库时两处保存同一份读数。
- **动作回写变更清单**：洁净区每次成功动作都向变更控制追加一条 `CHAN-EM-xxxx` 联动记录
  （类别「环境监测联动」、状态「评估中」、超标动作带异常标记）。
- **存量迁移**：首次读取 localStorage 时对旧洁净区记录做幂等迁移——按点位回填归属区与培养基批号、
  按监测日期回填当时轮值周次与监测人（待监测记录监测人留空）、复核份读数回填为原读数。
