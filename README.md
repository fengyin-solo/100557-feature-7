# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。

## 洁净区环境监测归属与合规规则

归属、轮换与校验规则集中在 `frontend/src/data/cleanroom-policy.ts`，判定只在
`local-service.ts` 的洁净区分支执行，页面不做业务判断：

- **点位划片归属**：生产区按监测点位划片（点位清册登记归属区与洁净级别）；点位落在哪个区，
  只有该区**本周当值监测人**能提交监测、判定达标、标记超标，越权一律拒绝并写明
  「归属区 / 当值人 / 当前操作人」原因。
- **监测人每周轮换**：按 ISO 周号在各区监测人名单里轮换，页面顶部展示本周值班表与当前操作人。
- **达标记录只读**：判定为「已达标」的记录整体转只读，本区与其他区的任何动作都动不了。
- **培养基批号对应点位**：批号形如 `前缀-年周-点位流水`（如 `MCA-2640-01`），
  前缀与流水随点位走，不对应则打回。
- **状态顺次推进**：只允许 `待监测 → 监测中 → 已达标/超标预警` 沿登记的后继边往下走，
  倒序、跳步一律挡回。
- **超标标记幂等**：同一记录已在「超标预警」时，重复标记只算一次，不再重复回写变更控制清单。
- **动作回写变更控制**：提交监测 / 判定达标 / 标记超标均在变更控制清单生成
  `CHAN-CR-<记录号>-<动作>` 条目，同记录同动作只回写一次。
- **悬浮粒子数单一数据源**：两处取来的为同一份，只存、只显、只回写「悬浮粒子数」一个字段；
  旧数据里的重复字段迁移时合并进唯一字段后删除。
- **非法值打回重填**：悬浮粒子数只接受非负整数，空值、负数、小数、文字一律拒绝。
- **存量迁移**：本地数据带 schema 版本（当前 v2），旧记录在首次加载时按旧记录回填
  归属区、洁净级别、培养基批号、监测人等缺失字段，占位点位映射到真实划片点位，
  非法粒子数清空待重填；迁移幂等，完成后写回版本号。
